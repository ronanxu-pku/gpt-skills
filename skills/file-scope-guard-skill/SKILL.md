## 文件授权

agent 只能修改用户 prompt 明确指定且已获授权的文件。

文件必须具有明确名称及可确定的位置。
只指定目录、模块或“相关文件”，不构成精确文件授权。
未指定确切文件时，必须询问；可以先只读检查并提出文件清单，
但不得自行选定文件后开始修改。

相对路径可以接受，但必须能够确定其所属工作树。
存在多个同名文件时，先确认目标。

新增、修改、删除、重命名均受此规则约束。
获准修改一个文件，不代表获准创建同目录下的其他文件，
也不代表获准修改其调用方、测试、配置或文档。

发现需要连带修改时，列出额外文件及原因，取得授权后再执行。
已经明确授权的文件和操作不重复询问。

## 自动生成文件

已授权的同步、依赖同步或运行操作产生的 .cache、__pycache__、
.pyc 等常规工具缓存，可以自动创建，无须逐个批准。

该例外不允许：
- 主动新增源码、脚本、配置、文档或报告。
- 创建、删除或重建环境。
- 借缓存名称保存与任务无关的内容。
- 自动清理、删除已有文件或缓存。

模型下载、数据同步和运行输出，应在操作获授权时明确目标位置；
不需要逐个批准工具必需的分片、下载元数据或输出文件。
这不构成额外下载、运行或创建环境的授权。

## 专项权限

环境操作遵守 uv-project-skill。
README.md 和 Implementation.md 的内容编辑遵守 doc-skill。
Git 暂存、提交和推送遵守 git-commit-skill。

其他 skill 中描述的默认目录、命令或维护流程，不构成文件修改授权。

共享规则与项目独有规则的冲突、修改及更新方式，遵守
[skill-update-skill](../skill-update-skill/SKILL.md)。
