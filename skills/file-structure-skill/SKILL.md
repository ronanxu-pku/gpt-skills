## 项目外层结构

多个代码分支使用各自独立的 Git worktree 目录。
worktree 指同一仓库中供某个分支独立工作的目录。

项目默认结构为：

```text
项目根目录/
├── <用户指定名称的代码工作树>/
├── data/
└── skills/
```

data 是项目共享的数据工作树，用于维护数据位置记录、
获授权的数据同步脚本及忽略规则。
权重和评测数据本体不进入 Git。

skills 是独立 gpt-skills 仓库的引用或工作目录，
不再维护一份属于业务仓库 skill 分支的重复技能副本。
使用链接、独立检出或 Git 子模块的具体方式由用户决定。
项目独有 skill 与共享来源分开维护，冲突与更新遵守 skill-update-skill。

各代码工作树、分支及新增功能目录名称由用户指定。
目录存在不意味着可以自行新增文件。

## 代码工作树内部

默认结构为：

```text
代码工作树/
├── env/
├── scripts/
│   ├── python/
│   └── bash/
└── run.py
```

env 保存环境声明和环境，具体规则见 uv-project-skill。

scripts/python 保存 Python 辅助脚本。
scripts/bash 保存 Bash 辅助脚本。
需要继续按功能划分子目录时，名称必须由用户指定。

run.py 位于代码工作树根目录，作为基础推理入口。
辅助实现放在对应脚本位置，不把一次性操作都扩展成新脚本。

## 内容职责

每个目录、文件、章节和配置字段只保存符合其用途的内容。

- 数据位置、版本和核验状态属于 data/locations.json。
- 依赖声明属于环境配置。
- 执行配置属于项目已指定的执行入口或配置文件。
- 文档职责和编辑权限遵守 doc-skill。

有用但用途不同的内容不能为了方便而塞进当前文件。
需要新文件时，先提出确切文件路径并取得授权。

这些结构是新项目的默认方案，不构成创建目录、文件、工作树
或迁移现有项目的授权。
已有结构需要调整时，先列出受影响文件及迁移方案。

共享规则与项目独有规则的冲突、修改及更新方式，遵守
[skill-update-skill](../skill-update-skill/SKILL.md)。
