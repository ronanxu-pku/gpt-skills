## 默认权限

agent 不得擅自执行 git add、git commit 或 git push。
修改文件的授权不等于暂存、提交或推送授权。

可以只读检查状态、差异、历史和暂存区，
但不得修改与本次任务无关的暂存内容。

此规则取代旧技能中“技能更新后自动提交并推送”的默认要求。

## 阶段性提交提案

在 milestone，即一个可独立验收的工作阶段完成时，提出：
- 拟提交的确切文件清单。
- 主要改动及其目的。
- 已完成的验证及未完成项。
- 完整提交信息，包括标题和正文；无正文时明确说明。
- 是否包含新增、删除或重命名。

提案在对话中展示，不自行创建提案文档。

提交标题采用：
类型: 中文内容描述

例如：
feat: 增加模型推理入口
fix: 修复数据位置记录更新逻辑
docs: 明确环境配置步骤

类型可以使用 feat、fix、docs、refactor 等常见标记，
描述和正文使用中文；技术名称可以保留原文。

## 审阅与执行

用户审阅、修改或确认完整提案，并授权执行后，
才能暂存并提交批准的文件。

审阅后若文件内容、提交范围或提交信息发生实质变化，
先重新展示变化并取得确认。

使用明确文件清单，不使用 git add . 或 git add -A
顺带暂存其他文件。

已有无关暂存内容时，不把它们纳入本次提交，
也不自行取消用户已有的暂存操作。
不能确保提交范围时，先说明问题。

提交完成后报告提交标识、实际文件范围和结果。
失败时如实报告，不将提案或本地修改描述为已提交。

推送需要单独授权，或已明确包含在本次获批操作中。
不擅自强制推送、改写历史或合并分支。

共享规则与项目独有规则的冲突、修改及更新方式，遵守
[skill-update-skill](../skill-update-skill/SKILL.md)。
