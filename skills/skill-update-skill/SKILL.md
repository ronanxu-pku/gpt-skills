## 共享来源与项目独有技能

gpt-skills 是独立 Git 仓库，维护供多个项目引用的共享技能。
项目可以维护自己的独有 skill，具体文件位置须经用户批准。
项目独有技能与共享来源分开保存，不通过修改共享文件实现项目定制。

应用规则时，先识别当前项目引用的共享技能和适用的项目独有技能。
在系统、开发者指令及用户明确指令允许的范围内：
- 用户当前明确要求优先于技能中的默认约定。
- 项目独有 skill 与 gpt-skills 冲突时，默认采用项目独有规则。
- 未被覆盖的共享规则继续适用，不因局部冲突而丢弃整份共享技能。

项目独有技能应说明适用项目、作用范围及覆盖的共享规则。
优先级是 agent 应遵守的规则，不假定工具仅凭同名技能就自动覆盖。
只有名称相同、没有明确适用范围时，先核对内容，不能猜测归属。

## 修改归属与授权

用户只要求调整当前项目行为时，提出项目独有技能的修改方案，
不擅自修改 gpt-skills，也不自动复制整套共享技能。
新增或修改文件遵守 file-scope-guard-skill。

用户明确要求修改 gpt-skills 时，可以在批准的确切文件内修改共享来源。
先确认实际文件路径及链接目标，说明共享改动影响所有引用该规则的项目。
不得把指向共享文件的软链接误认为可独立修改的项目副本。
用户已经批准的共享修改无需再逐个请求引用项目批准。

共享更新由所有采用更新版本的项目共同遵循；
项目已有的明确专用覆盖规则仍默认优先。
若用户要求连项目覆盖规则一并统一，另按指定文件范围修改，
不能借共享更新自行删除项目专用技能。

## 更新与传播

共享技能只在 gpt-skills 来源中维护，不在各引用项目另存重复版本。
项目通过软链接指向同一个本地来源时，来源文件更新即反映在引用文件中；
报告实际文件变化，不把它等同于所有已运行会话都已重新加载。

其他机器的独立检出需要更新仓库；固定提交的 Git 子模块需要更新引用。
这些情形不能声称已经自动同步。
在获授权的范围内完成所需同步；未同步的位置如实报告。
推送、提交以及修改项目中的固定版本引用仍遵守 git-commit-skill
和 file-scope-guard-skill，不因要求共享更新而自动获得这些权限。

## 校验与提案

修改后检查技能名称、描述、文件引用和规则一致性，
尤其核对文件授权、环境审批、文档权限及 Git 审阅流程。
不为当前项目的临时需求加入无关服务器地址或绝对路径。

完成一个可审阅阶段后，按 git-commit-skill 提出完整提交方案。
构建或修改技能的授权不等于暂存、提交、推送或迁移其他项目的授权。
