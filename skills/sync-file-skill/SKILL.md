## 本地修改

源码、脚本、配置和其他可维护项目文件，必须在本地工作树或本地目录修改。
编辑、重命名等文件修改命令在本地执行，不通过 SSH 直接修改远端源码。

修改范围遵守 file-scope-guard-skill。
文档的特殊权限遵守 doc-skill。

先进行与改动相关的本地检查，再同步。
本地无法完成的验证应明确说明，不把未验证描述为通过。

## 文件同步

同步前明确：
- 本地工作树及源文件。
- 目标服务器和目标路径。
- 本次同步的具体文件清单。

只同步获授权的文件，不默认同步整个工作区。
排除 .git、.venv、缓存、模型权重、评测数据及运行输出。
数据传输使用 sync-data-skill。

默认不使用 --delete，不删除远端额外文件。
若目标存在来源不明或可能未保存的改动，先核对，不直接覆盖。

同步后比较文件校验信息，确认远端内容与本次本地文件一致。
失败时报告实际完成和失败的文件，不声称全部同步成功。

同步工具产生的常规缓存按 file-scope-guard-skill 处理。

## Git 与部署身份

文件同步不强制要求先提交 Git。
不得为了同步而擅自 git add、commit 或 push。

若同步包含未提交修改，记录或报告：
- 当前已提交版本。
- 本次同步文件清单及校验信息。
- 存在未提交修改这一事实。

不得把含未提交修改的部署描述为某个提交的完整复现。
需要写入新的部署记录文件时，先取得该文件的授权。

## 远端执行

从本地发起 SSH，执行已获授权的远端环境安装或推理命令。
执行前检查所选服务器资源及已有任务。

远端可以执行依赖安装、数据下载和项目运行；
不得借这些操作临时修改源码或依赖声明。
创建、删除或重建环境仍须用户批准。

不擅自新增实验、监控或终止已有任务。
分别报告文件同步、环境检查和实际运行结果。

共享规则与项目独有规则的冲突、修改及更新方式，遵守
[skill-update-skill](../skill-update-skill/SKILL.md)。
